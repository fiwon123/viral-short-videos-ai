# Viral Short Videos

For channel discovery, channel branding, reference breakdowns, and episode production, read [.agents/skills/viral-video-studio/SKILL.md](.agents/skills/viral-video-studio/SKILL.md). It defines the user's decision points and the local production workflow. Run tools from the repository root. See [README.md](README.md) for commands and [studio/schema.json](studio/schema.json) for the data contract.

Prefer one workspace per channel: `workspace/<slug>/channel/channel.json`, `workspace/<slug>/episodes/<episode>/episode.json`, `workspace/<slug>/research/`, and `workspace/<slug>/renders/`. The legacy `channels/`, `episodes/`, `research/` and `output/` layouts remain readable; `make migrate CHANNEL=... EPISODE=... APPLY=1` moves one channel when you want to consolidate it. Keep local source videos under `reference-media/`. Run `make channel-doc` after editing `channel.json` to refresh the copy/paste `channel.md`. The tracked `examples/` folder is a public showcase; `workspace/`, `channels/`, `episodes/`, `research/`, `reference-media/` and `output/` are local. Version the reusable studio, presets and skill. Keep API keys in the environment.

`make help` lists the local shortcuts, `make status` shows what channel and episode resolve to and whether each uses the workspace layout, `make assets` reports the channel files an episode render actually reads, and `make prune-<group>` (dry run; add `APPLY=1`) removes assets that no render uses. Never prune a file a channel manifest still points at. `make sound RECIPE=...` and `make effect RECIPE=...` generate custom audio and SVG recipes. Per-machine defaults live in an ignored `.env` (see `.env.example`); nothing about a specific channel belongs in tracked files.
