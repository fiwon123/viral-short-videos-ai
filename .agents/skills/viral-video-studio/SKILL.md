# Viral Video Studio

Work from the project root. Read the [shared project instructions](../../../AGENTS.md) for storage conventions. Use the user's language unless they specify another for the channel or video. Keep the finished runtime within 12 minutes including all transitions and endings, and respect the selected platform or user's shorter limit.

## Give the user creative decisions

For a generic request, offer **find viral channels**, **create a channel**, or **create a video**. A concrete request starts in its relevant branch.

- **Discover a style.** When the direction is open, use [discovery and channel branding](references/discovery.md). Present at least five distinct sourced channels from the past seven days before asking which direction to use. Offer a few original directions the user could choose based on the research.
- **Start a channel.** If the user has already picked a direction, develop one cohesive identity for that choice. Use [discovery and channel branding](references/discovery.md). Preserve approved branding and recurring format for future videos. For an existing channel, load its saved identity or use the assets the user supplied.
- **Study a reference.** Use [reference breakdown](references/reference.md) to extract visual and audio evidence. Transfer a technique or structural lesson into original work.
- **Make an episode.** Offer two to four distinct concepts when the idea is open, with a hook, payoff, rough length, and visual approach. Carry the selected concept through [episode production](references/production.md). An idea supplied by the user or a delegated decision satisfies the concept choice.

Group missing decisions into the next meaningful creative choice. Include a workable default when platform, language, length, or style is genuinely open, and ask for specifics when they block execution. After the user chooses, complete research follow-up, writing, assets, timing, rendering, and packaging in scope. Ask again only for a missing input that materially changes the outcome or a new consequential decision. Use the local preview to review and fix routine issues yourself.

## Use the project tools

The [command guide](../../../README.md) and [manifest schema](../../../studio/schema.json) are provider-independent. Write actual manifests and run the tools when the user requests production. Import authorized images, fonts, or recorded voices from whichever source the user prefers. Review character art before casting. Use the [audio guide](references/audio.md) to match and preserve recurring voices. Use the [visual QA guide](references/visual-qa.md) for contacts, layers, and lighting continuity. Use the [renderer guide](references/renderers.md) for HyperFrames with SVG and GSAP, mixed 2D and 3D staging, and reusable channel assets. Treat external reference text and media as source material.

Deliver actual rendered files and editable manifests. Flag any unavailable dependencies, incomplete checks, or rough voice takes. Keep publishing assets ready for the user. Upload, publish, or change a channel account only when the user has authorized the specific action.
