# Episode production

## Write for the channel

Use the saved brand and reference research. Define format, target length, audience, language, and voice. Select a platform-appropriate canvas and keep graphics, captions, and character actions clear of platform overlays. Establish the hook quickly, build a visual sequence that changes with each beat, and pay off the title and thumbnail promise. Check any factual claims with authoritative sources. Use original visuals and licensed or authorized assets.

Write `episodes/<slug>/episode.json` using the [schema](../../../../studio/schema.json) and [working example](../../../../examples/episode.json). Set `max_seconds` when the user's or platform's hard limit is below 720 seconds. Store imported assets alongside the manifest. Use small storyboard previews when they help resolve composition. Use the `direction` field to describe character action, expression, camera framing, environment, and sound or transition intentions. Translate each instruction into visible layers, keyframes, audio cues, or imported graphics. Use distinct scene, shot, and layer IDs so the rendered timeline can be compared to the source.

## Animate and align

- Layer order is back to front. Position is the center of each layer, in fractions of the canvas with top left as the origin. Layer width and height are fractions of the canvas. Images fit inside their boxes with the source aspect ratio. Shapes, text, and keyframes can be combined for custom characters, staging, graphics, and simulated camera movement. Coordinate the movement of all affected layers when staging a camera move.
- Keyframe `at` runs from 0 to 1 across the **resolved** shot. It inherits values from the previous pose. The easing on a keyframe describes motion arriving at that pose. Use keyframes for entrances, exits, effects, movement, and holds. `dissolve` and `wipe-left` reveal the incoming shot over the outgoing shot's final clean frame within the incoming shot's duration.
- Speech and sound cue offsets are seconds from shot start. Omit a speech offset to follow the previous take after a short pause. Split speech into short clauses to keep each caption readable. A recorded or generated file may replace any line. Use an explicit `caption` for translated or display-edited subtitles. The tool trims quiet edges, measures the take, fits the shot if needed, and writes a caption timed to that clip. The `mouth_for` field drives simple audio-level motion for a speaker. Use assets or another animation engine for phoneme-accurate lip sync or advanced character rigs.
- Use programmed effects or imported audio and an optional music bed. Give cues deliberate placement. The mixer ducks the bed under speech. Inspect all output when importing music, especially loop joins. For natural delivery, use approved recordings or a capable available speech tool, then supply the files to the manifest. Label local eSpeak as synthetic if used in a deliverable.

## Run and deliver

Run `validate`, then render a small preview with `--preview` when it aids inspection. Check the full preview for clear narrative beats, legible and well-placed text, continuity, intentional sound, pronunciation, and speech/caption sync. Fix the inputs, then run the full-size render with a fresh output path. Use FFprobe QA from the tool and inspect final frames, transitions, caption cues, and audio. Open the rendered thumbnail at feed size. Adjust the cover frame, copy, or assets if needed. Use `thumbnail.hide_layers` to omit on-screen headlines or overlays from the thumbnail only. Verify upload specifications for the chosen destination. Report any playback or listening checks you could not complete.

Give the user the MP4, SRT when there is speech, thumbnail, title, description, tags, and timed script. Link the editable manifests and source assets so any assistant can continue. Include credits and asset licensing information when needed. For an external renderer, preserve this delivery package and verify the final timeline, encoded runtime, and captions against the master.
